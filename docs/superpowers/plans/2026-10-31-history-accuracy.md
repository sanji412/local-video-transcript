# History and accuracy implementation plan

按 writing-plans、test-driven-development 和 subagent-driven-development 执行。用户已批准实现范围，不再重复请求设计确认。

1. 后端：先编写持久化/并发版本/重启/API/模型模式测试并确认失败；实现 SQLite 历史库、成功结果事务保存、历史接口、双模型配置与任务模式；通过测试后提交。
2. 前端：先写历史/自动保存状态/切换保护/版本冲突/模式准备测试并确认失败；实现历史面板及文稿加载、保存状态、原稿对照、模式选择；通过交互测试、类型检查和构建后提交。
3. 验证：对相同真实口播运行快速/精确模型，检查同音词、漏字与耗时，记录结果；完整回归，独立代码审查，真实浏览器操作和启动验证后提交说明。

接口约定见本次任务 brief，后端先冻结契约再接入前端。各任务只修改自己负责文件，父代理负责集成提交，保留用户现有数据。
