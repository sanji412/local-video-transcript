# 视频文案提取器：MVP 产品设计

日期：2026-10-21

状态：产品范围已确认；实现与验证情况见[验证记录](../../validation.md)。

## 1. 产品定位

一款在本地运行的视频文案提取工具，主要面向抖音口播、知识讲解类视频。用户粘贴视频链接，即可获得完整的讲述稿，方便阅读、保存和研究脚本。

“文案”指视频中完整的讲述内容；通篇字幕可以作为文案来源。不提取发布标题、描述、评论，不主动总结、改写或补充原文。

首版优先服务个人使用，目标运行环境为当前的 Apple M5、16GB 内存 Mac。

## 2. 核心原则

- **本地处理**：不使用在线转写服务，不上传音视频或文案；下载视频需要联网，识别模型首次使用时需要下载。
- **完整优先**：提取完整讲述稿，保留原意；允许添加基础标点和分段，便于阅读。
- **操作简单**：以单条视频提取为核心，一次完成一个任务。
- **结果可校对**：用户可以修改识别错误，复制或导出最终文本。

## 3. 使用流程与界面

产品形式为本地网页工具，启动后在浏览器使用。

首次使用：检查本地识别模型；缺少模型时，提示下载及进度，完成后即可使用。模型已就绪时，导入本地视频不需要联网转写。

日常流程：

1. 粘贴抖音链接或整段分享内容，也可以选择本地视频文件。
2. 点击“提取文案”，查看下载和转写等阶段状态。
3. 阅读完整文案，按需编辑。
4. 一键复制全文，或导出 TXT 文件。

主界面包含输入区、处理状态区和文案结果区。结果区标注“字幕提取”或“语音转写”，首次使用时提供模型准备提示。

## 4. 主要功能

| 功能 | MVP 范围 |
| --- | --- |
| 链接识别 | 支持抖音分享短链接和单条视频链接，从整段分享内容中识别链接；多条链接提示用户只保留一条 |
| 视频获取 | 获取单条可访问的公开视频；失败时说明原因，并提供重试及本地文件导入入口 |
| 本地视频导入 | 支持 MP4 文件，作为独立输入方式及链接获取失败后的替代入口 |
| 完整文案提取 | 能获取完整、可独立读取的字幕时优先使用；字幕不可用或不完整时，使用本地语音识别生成全文 |
| 结果编辑 | 展示带基础标点和分段的全文，支持手动编辑；不将摘要代替全文 |
| 复制与导出 | 复制当前编辑后的全文，或将其导出为 UTF-8 编码的 TXT 文件 |
| 任务反馈 | 展示解析、下载、转写等实际阶段，支持取消和失败重试；不显示无法可靠估算的百分比 |
| 临时文件清理 | 任务结束、失败或取消后清理本工具生成的临时音视频；不删除用户导入的原文件和主动导出的文案 |

字幕能否获取、是否完整，需要在技术验证时确认。无法确认完整性时，默认转写全段音频。画面中嵌入的字幕不属于可独立读取的字幕，首版不做画面文字识别。

## 5. 首版边界与异常处理

- 优先支持普通话口播及讲解视频，时长不超过 30 分钟；超出范围时明确提示。
- 链接获取成功率、转写速度和准确度需使用真实样本验证，不承诺所有抖音链接均可获取。
- 语音转写还原实际讲述内容，可能与画面中经过编辑的字幕存在差异；专有名词等允许用户校对。
- 链接无效、视频不可访问、下载失败、模型未就绪或转写失败时，给出明确提示及可执行的下一步。
- 无法识别有效语音时提示用户，不用编造文本填充结果。
- 首版不做批量提取、作者主页抓取、多平台支持、画面字幕识别、AI 总结改写、复杂历史管理或云端同步。
- 首版不提供跨会话历史；界面保留当前结果供编辑，关闭工具前由用户自行复制或导出。

## 6. 验收场景

以下场景作为后续开发的主要验收测试，需在实现后执行。

| 场景 | 预期结果 |
| --- | --- |
| 粘贴包含一个抖音链接的分享文案 | 能识别目标链接并开始处理；输入多个链接时提示只保留一条 |
| 处理有完整可获取字幕的视频 | 输出完整字幕文案，结果来源标注为“字幕提取” |
| 处理无可用完整字幕的普通话视频 | 在本机转写全段音频，结果来源标注为“语音转写” |
| 模型已就绪，断网导入本地 MP4 | 可以完成转写，处理期间不依赖在线转写服务 |
| 编辑结果后复制或导出 | 内容与编辑后的全文一致，TXT 中文显示正常 |
| 无效链接、下载失败或模型未就绪 | 提示对应原因及下一步；可按情况重试、准备模型或导入本地文件 |
| 取消任务或任务失败 | 任务停止或退出，临时音视频得到清理，原始文件不受影响 |
| 导入超过时长上限或无有效语音的视频 | 给出清晰提示，不伪造完整文案 |

## 7. 成功标准与后续方向

首版成功标准是跑通“输入视频 → 本地提取全文 → 校对 → 保存”的完整流程。使用一组真实口播、讲解视频，分别记录链接获取成功率、全文完整性、文字准确度和处理耗时，再决定优化重点。

后续根据实际使用反馈，考虑画面字幕识别、批量任务和本地历史记录；本地处理仍是默认原则。
