# 视频文案提取器：MVP 技术方案

日期：2026-10-21

依据：[MVP 产品设计](superpowers/specs/2026-10-21-video-transcript-mvp-design.md)。技术路线已确认，本文说明首版的总体实现方向，不展开接口字段和代码细节。

## 1. 总体方案

采用本地网页架构：React 界面负责输入、状态展示和文案编辑，Python 服务负责视频获取、音频处理和本地转写。

首版面向当前 Apple M5、16GB 内存 Mac，优先支持普通话、10 分钟以内的单条口播或讲解视频。所有转写在本机完成，不调用在线转写服务，不上传音视频或文案。

浏览器通过本机 HTTP 接口与服务通信。视频获取和首次模型下载需要联网；模型就绪后，本地视频转写应可以断网完成。

## 2. 技术栈

| 部分 | 选择 | 职责 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 链接及文件输入、任务状态、全文编辑、复制和 TXT 导出 |
| 后端 | Python + FastAPI + Uvicorn | 输入校验、任务管理、模型准备和结果返回 |
| 视频获取 | yt-dlp，先验证后接入 | 解析抖音链接，获取视频及可用字幕 |
| 音频处理 | FFmpeg + ffprobe | 读取时长、检查音轨、抽取并转换音频 |
| 本地识别 | mlx-whisper | 在 Apple 芯片上运行 Whisper 模型，生成完整讲述稿 |
| 数据管理 | 内存状态 + 本地文件 | 保存当前任务状态、临时媒体、模型及少量配置 |
| 工程管理 | uv、npm 及各自锁文件 | 管理 Python 和前端依赖，固定验证过的版本 |
| 测试 | pytest、Vitest + React Testing Library | 验证后端流程与前端交互，另做真实视频端到端验收 |

首版无需数据库、Redis 或外部任务队列。运行时使用一个 API 服务进程，并按需启动一个工作进程处理当前任务。

## 3. 模块分工

| 模块 | 职责与边界 |
| --- | --- |
| 网页界面 | 接收输入、轮询状态、编辑全文；复制和导出使用编辑后的文本 |
| 任务管理 | 创建任务、限制同时只有一个活动任务、协调取消重试、记录阶段与错误 |
| 视频获取 | 从分享内容识别单条链接，调用 yt-dlp 获取媒体和字幕；向上层返回统一结果，便于以后更换获取工具 |
| 内容提取 | 判断字幕是否可用，否则通过 FFmpeg 和 mlx-whisper 转写完整音频；不依赖抖音链接格式 |
| 本地资源管理 | 检查及下载模型、创建任务临时目录、清理媒体与记录必要诊断信息 |

长耗时工作放在独立工作进程中，避免阻塞 API。Mac 使用明确的进程启动方式，在工作进程内加载模型，避免在主进程加载后再复制进程。首版任务结束后释放工作进程及其模型内存，接受下一次任务重新加载模型的开销。

## 4. 核心处理流程

1. **准备模型**：检查本地模型是否完整；缺失时提供下载入口和进度。下载完成后校验可加载性，失败时允许重试。
2. **接收输入**：校验单条抖音链接或 MP4 文件；多个链接、文件无效等情况直接提示。
3. **获取媒体**：链接任务先解析、下载；本地文件任务将导入内容写入任务专属临时目录。检查实际媒体时长不超过 10 分钟。
4. **选择文案来源**：完整、可独立读取的字幕优先；缺失、解析失败或无法确认完整性时，转写全段音频，不将片段字幕当作全文。
5. **本地转写**：FFmpeg 将音轨转换为识别使用的音频，mlx-whisper 输出全文及分段；保留原意，不调用大语言模型改写或补充内容。
6. **返回和清理**：结果转移到 API 进程内存，标注“字幕提取”或“语音转写”，清理临时媒体；用户在网页中校对、复制或导出。

字幕获取及完整性判断属于前期验证项。首版只有在可获取字幕、内容可解析且时间覆盖合理等检查通过后才采用字幕；这些检查无法证明逐字完整，仍需真实样本人工核对。证据不足时默认语音转写。嵌在画面中的字幕不做 OCR。

## 5. 任务、存储与本地访问

- 前端创建任务后获取任务 ID，以简单轮询读取当前阶段和结果。首版展示阶段名称，不承诺精确剩余时间。
- 同时仅允许一个活动任务；忙碌时提示等待。失败重试创建新任务，避免沿用不完整文件。
- 取消时终止工作进程及其启动的下载、转码子进程，确认退出后清理临时目录，再进入取消状态。
- 模型文件和应用配置持久保存在用户目录；临时媒体按任务隔离。当前文案和状态只保留在内存，不提供跨会话历史。
- 清理仅作用于工具自己的临时目录，不删除用户原视频或主动导出的 TXT；异常退出留下的任务目录在下次启动时清理。
- 服务仅监听 `127.0.0.1`。日常使用由 FastAPI 同时提供构建后的网页和 API，前端资源不依赖外部 CDN。
- 接口检查请求来源，修改状态的请求使用本地会话令牌；限制上传大小、下载大小和超时。仅接受抖音链接，并校验重定向，避免将服务变成任意网址下载器。
- 不自动读取浏览器 Cookie。若验证发现必须提供抖音 Cookie，再设计用户主动配置的本地入口；日志不得记录 Cookie 或完整文案。

## 6. 模型选择与优先验证项

识别引擎优先选 mlx-whisper，模型先比较 Whisper medium 与 large-v3-turbo 的多语言版本，使用实际普通话样本决定默认配置，不将所有候选模型都作为首次必需下载。

模型下载与推理分开：准备阶段下载并缓存模型，推理阶段显式加载本地路径，防止转写时隐式联网。首版只设置一个经过验证的默认模型，不提供复杂参数面板。

| 验证项 | 观察内容 | 对方案的影响 |
| --- | --- | --- |
| 抖音视频获取 | 常见分享链接、访问条件、失败原因及成功率 | 确定 yt-dlp 是否足够，是否需要额外获取适配；保留本地 MP4 入口 |
| 字幕可用性 | 是否能获取独立字幕，是否完整，是否与讲述对应 | 决定哪些情况采用字幕；证据不足就转写全文 |
| 本地模型效果 | 中文错字、专有名词、遗漏和重复、耗时及峰值内存 | 选择适合当前设备的默认模型，并固定版本 |
| 音频质量 | 静音、背景音乐、较弱人声 | 检查无有效语音提示，评估是否需要增加语音活动检测 |

这些结果需要通过真实运行获得，当前方案不宣称已验证下载成功率、M5 性能或字幕完整性。

## 7. 测试与验收

以下为实现阶段应编写和执行的测试规格；本次交付仅为技术文档，不代表应用测试已经通过。

| 层级 | 主要场景与预期 |
| --- | --- |
| 后端单元测试 | 分享内容识别、多个链接拒绝、时长上限、字幕不完整时切换到全文转写 |
| 任务集成测试 | 使用替代下载器和识别器验证状态流转；失败可重试，重复提交不并发处理 |
| 进程与清理测试 | 取消下载或转写后子进程退出；成功、失败及异常重启均清理临时媒体，不影响原文件 |
| 前端交互测试 | 处理中状态、失败提示、结果来源、取消操作；复制及 TXT 导出与编辑后的全文一致 |
| 模型准备测试 | 模型缺失、下载失败及文件损坏均可恢复；不会把不完整模型当作就绪 |
| 离线验收 | 模型已就绪后禁止外网访问，导入本地 MP4 仍可完成全文转写 |
| 真实视频验收 | 覆盖普通话口播、知识讲解、字幕不完整、无有效语音等样本，人工核对完整性并记录准确度和耗时 |
| 本地访问测试 | 服务只绑定本机；拒绝非抖音输入、违规重定向、超限文件和未授权的跨来源操作 |

自动化测试默认不访问抖音、不下载模型；真实网络与模型测试单独执行。开发交付前，应完成与改动相关的测试及产品文档中的验收场景，并明确报告失败或尚未验证的部分。

## 8. 实现顺序与暂不引入的能力

建议依次完成：真实样本技术验证 → 本地 MP4 转写流程 → 抖音链接获取和字幕分支 → 网页交互与异常处理 → 一键启动及整体验收。

开发时分别运行 Vite 和 Python 服务；日常使用通过启动脚本启动本地服务并打开浏览器，不要求用户手动启动前端开发服务器。后续需要分发给他人时，再处理桌面安装包及跨平台识别引擎。

本版不引入云端服务、在线转写、数据库、批量任务、画面字幕 OCR、AI 总结改写或桌面外壳。
